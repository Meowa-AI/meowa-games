# HD2D 战斗表现改造计划

## 目标

把当前由 CSS 渐变、椭圆站台和普通图片组成的战斗页，改造成真正位于 Three.js 世界中的 HD2D 战斗场景。视觉方向参考用户提供的森林战斗截图，但不逐像素复制其界面或素材。

战斗逻辑继续由 `BattleEngine` 负责；本计划只重构表现、镜头、输入界面和资源接入。

## 核心方向

- 战斗切换到独立的林间圆形场地，不复用或克隆当前大世界森林节点。
- 玩家宝可梦位于左下近景，敌方位于右侧中景。
- 宝可梦正面和背面像素图以 3D Billboard 进入场景，拥有世界坐标、脚底锚点和接触阴影。
- Three.js 负责地形、透视、遮挡、光照、阴影与后期；DOM 只负责状态牌、消息和指令菜单。
- 战斗结束后恢复原相机、玩家、NPC、输入和世界状态。
- 四周以密集高树形成封闭环，不再为天空单独留缺口；放大的草簇在树墙前形成前景层。

## 素材契约

当前精灵范围为开局六种，素材由 Meowa 参考编辑后接入：

- 静态回退为 3×2 图集，每个单元 64×64 RGBA；正面图集同时供战斗头像和御三家选择使用。
- 战斗优先使用六种精灵的 33 张待机、叫喊、受击动画图集；土狼犬正面使用静态回退。
- 动画保持原帧尺寸、排列、帧数、播放速度和透明脚底锚点。
- 采样使用 `NearestFilter`，不生成 mipmap；透明裁切并保留深度写入。

第一阶段后续视觉修正新增一张战斗高台顶面素材：

- 类型：Meowa 生成并经像素背景移除的 `128x128` RGBA PNG。
- 内容：俯视圆形短草外圈和踩实泥土中心。
- 森林圆盘顶面使用
  `assets/runtime-source/battle/platform/battle-platform-top.png` 的原始
  128×128 RGBA 像素图，运行时副本为 `public/assets/battle/platform/battle-platform-top.png`；
  使用完整 UV 的贴地透明平面，不重采样图片。
- 已移除 PSKX、圆柱土层、底座、平台阴影和独立小草；玩家精灵脚底上移 0.04，
  敌方精灵脚底下移 0.02，接触阴影仍固定在地面。
- 用法：只作为圆柱高台顶盖纹理；土层侧壁、草沿和底座由 Three.js 几何表达。

后续若新增 UI 或特效素材，应先固定尺寸、透明度、采样方式、切片方式和运行时路径。

战斗 UI 使用 Meowa 编辑后的 PNG：24×24 框保留 CSS `border-image-slice: 6 fill`，显示边宽 8px；动作图标位于 `battle/ui/`。

林间场地使用 Meowa 地面、树冠、草簇和岩石变体，天空也经 Meowa 参考编辑后按原顺序打包为 512×3072 六面条带。完整来源及替换记录见 `assets/provenance/`；最终素材由 `scripts/prepare_assets.py` 按白名单发布。

## 架构

```text
BattleController / Game
├── BattleEngine            回合、伤害、PP 和胜负
├── BattleScreen            战斗流程与 DOM HUD
├── BattleStage             场景、锚点、精灵、站台和相机
├── BattleTimeline          入场、攻击、受击与倒下演出
└── BattleHud
    ├── StatusPanel
    ├── MessagePanel
    ├── CommandMenu
    └── MoveMenu
```

`DramaticShapeVoxelMod` 仅作为职责划分参考。它的 Lua 渲染代码不直接移植；对应的 `BattleStage`、`BattleCam`、`BattleDOF`、`BattleBillboard` 和 `BattleHud` 由 TypeScript/Three.js 重新实现。

## 画面构图

- 使用低于探索模式的相机俯角和较窄 FOV。
- 玩家站位靠近相机、偏左；敌方站位更远、偏右。
- 双方之间保留攻击演出空间。
- 战斗站台是贴近原地形的扁平 3D 草土层，不是屏幕空间椭圆。
- 宝可梦和站台均具有接触阴影，避免角色漂浮。
- 状态牌位于安全区；后续可升级为根据 3D 锚点投影并自动避让。

## UI 方向

- 状态牌使用深色半透明外壳、浅色内容层、像素切角和指向三角。
- 消息区位于屏幕中下方，不再横跨整个底部。
- 指令区位于右下角，采用 2x2 四象限按钮。
- 招式菜单复用指令区位置，显示名称、属性、PP 和威力。
- 键盘、鼠标和触摸共享同一个焦点状态。

## 进入战斗转场（BattleTransition）

仿 GBA 绿宝石野战节奏，全程 DOM 覆盖层实现（`src/battle/BattleTransition.ts`），
不依赖 PostFX 合成器开关状态，压在战斗 UI（z50）之上、选单弹窗（z60+）之下：

1. **反色闪屏 ×2**（约 0.33s）：`backdrop-filter: invert(1)` 快闪两次，不支持时退回白闪；
2. **像素漩涡收黑**（约 0.62s）：视口按 28px 方格划分，每格按
   `angle + radius·turns·2π` 的阿基米德螺旋序涂黑，黑边界旋转着从外圈卷向中心；
   画布不清屏、排序后游标只前进，每帧只补涂新格子；
3. **黑幕装配**：`BattleStage.create` 接收 `mountGate`（收黑完成的 Promise），
   纹理与环境资源在闪屏/收黑期间并行加载，全黑后才隐藏世界、接管相机；
4. **圆形揭幕**（约 0.48s）：黑幕以 `destination-out` 圆形从中心展开，
   与宝可梦入场动画并行；结束后覆盖层自毁。

`reduced` 画质（含 `prefers-reduced-motion`）退化为约 0.15s 的纯黑淡入淡出。
退出战斗仍走 BattleScreen 原有的斜纹幕布（现仅在 closing 时覆盖）。
螺旋排序为纯函数（`computeSwirlOrder` / `buildSwirlGrid`），由
`BattleTransition.test.ts` 覆盖区间、单调性与全覆盖性质。
